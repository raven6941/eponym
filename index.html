Eponym

Loosely, Epigram + Nim ~= Eponym. What if we took the influential system built by McBride and McKinna some 20 years ago, and implemented (some of) its ideas in Nim macros/metaprogramming? Eponym brings dependent types and quantitative type checking to Nim as an embedded DSL, so you can check the parts of a Nim program that benefit from stronger guarantees.

New here? Start with the tutorial (install → your first checked dependent type, ~15 minutes), look up any language form in the surface-syntax reference, and read the trust model to see what the system checks — and what is your problem.

Deliberate points of departure

QTT instead of ETT. Idris has demonstrated the 0/1/ω approach taken. This allows support for session types, and opt-in checking of the style popularized by rust.

Linear syntax is notably different to compromise with the macro approach to embedding in Nim.

Use cases

Eponym can encode and check correctness properties on just the libraries and pathways that need it, while code for specific use cases can remain in normal Nim. The examples show a few useful patterns:

  • Protocol state and message order — model a session as a type and make invalid operations, such as sending after close or accepting a value that was not promised, fail during compilation. See session_types.nim and paxos_session.nim.
  • Dimensions and shapes — index vectors and matrices by their dimensions so operations like dot product and matrix-vector multiplication require compatible sizes. See convex_opt_vec.nim.
  • Mathematical certificates — require a proof that an expression follows convexity rules before passing it to an optimizer. See convex_opt.nim and convex_opt_vec.nim.
  • Resource use and borrowing — check that a borrow is used exactly once, that its owner is not used while borrowed, and that the borrow does not escape its scope. See qtt_borrow.nim.
  • Interactive proof development — explore goals and contexts in the editor, then refine, finish, or split a proof into cases. See the shed walkthrough.

Why embedded

Eponym is deliberately not a standalone language. The goal is not to build and grow a full independent compiler, stdlib, package system, community around a new language. Rather, if only some of your program really calls for dependent typing, and some parts are fine with the type facilities already offered by Nim, then an embedded approach allows you to use the dependent types only where needed. I especially hope that libraries can host dependent reasoning, and use cases can get safety benefits whether or not they engage with dependent types directly.

Writing eponym in Nim code

The eponymBlock macro lets you write Eponym directly in Nim: ```nim import eponymmac import eponymembed

eponymBlock: import "lib/nat.ep" # shared prelude, not a per-file redefinition

data(Session, Univ): proc sendD(A: Univ, k: A -> Session): Session proc recvD(A: Univ, k: A -> Session): Session proc endS(): Session ... `` -Univmaps toType 0;?introduces holes anddiscards; call syntax for declarations (postulate(Int, Univ));procnotdef;=not:=— it reads as Nim, and the elaborator typechecks it at compile time. - Integer literals overload toNatviacheckTm(or primitiveInt). - Two-layer shape: the checked definitions are the proof layer; the surrounding Nim is the running layer, calling them through generated wrappers. - The headline demos inexamples/embedded/are built this way: paxossession.nim(Paxos as dependent session types with unforgeable promise tickets),convexoptvec.nim(DCP-checked logistic regression with dimension-indexed vectors),qtt_borrow.nim` (Rust-style borrow discipline checked at compile time).

Installation

Prerequisites: Nim >= 2.0 (built with 2.2.12 via choosenim) and nimble.

```sh nimble install eponym # from the nimble package directory (once published)

or, from a checkout of this repo:

nimble install ```

This installs the production modules (src/eponym/, issue #189) and the Eponym prelude (lib/*.ep) into the nimble package directory. Experimental code under src/experimental/ is deliberately not installed.

To use Eponym in your own project:

```nim import eponym_mac # eponymBlock macro

eponymBlock: import "nat.ep" # resolves relative to THIS Nim file ... ```

import "x.ep" inside eponymBlock resolves relative to the Nim file containing the block, so vendor the prelude files you need next to your project — copy them from the installed package's lib/ directory (~/.nimble/pkgs2/eponym-*/lib/). See examples/embedded/ for complete examples of ordinary Nim programs using Eponym-checked definitions.

Note: on first install nimble may prompt about a package-list download or about src/eponym/lib — answer yes / continue; the prelude is installed from the package root's lib/ directory.

Building

Requires Nim 2.x (built with 2.2.12 via choosenim).

```sh export PATH=$HOME/.nimble/bin:$PATH P="--path:src --path:src/eponym --path:src/relational --path:src/staging" for f in eponym eponyminit preterm parsesurf macsurf elab eponymmac egraph eponymembed; do nim c -r --hints:off $P src/eponym/$f.nim # build + run each test suite done nim c -r --hints:off $P tests/runexamples.nim # 36 .ep examples nim c -r --hints:off $P tests/fuzz_soundness.nim -- --seed 424242 -n 1000

(src/eponym/lsp.nim is built but not run: it is a server that blocks on stdin.)

```

REPL

An interactive read-eval loop — the fastest edit-check cycle for trying a definition, querying a type, or evaluating a term:

sh P="--path:src --path:src/eponym --path:src/relational --path:src/staging" nim c --hints:off $P src/repl.nim ./src/repl

eponym> :load lib/nat.ep add : Pi(Nat, m. Pi(Nat, n. Nat)) ... eponym> proc two : Nat = suc (suc zero) two : Nat eponym> :type (add two two) Nat eponym> :eval (add (suc zero) two) (suc (suc (suc zero))) eponym> :quit

Commands: - :type <tm>, - :eval <tm> (weak-head normal form), - :load<file.ep>, - :help, - :quit.

Anything else is Eponym source: declarations elaborate into the persistent session and stay in scope; multi-line declarations work, and errors print as located messages without killing the session. A scripted session is exercised in CI (tests/repl_session.sh).

Examples

Three kinds, reflecting the project's dual nature as both a standalone elaborator and an embedded Nim library:

  • examples/ep/ — 36 documented .ep surface-syntax programs, the elaborator's regression suite (run by tests/run_examples.nim), from basic twice through indexed Vec with append to negative cases for the session-type and borrow demos.
  • lib/ — the shared prelude: nat.ep, bool.ep, list.ep, vec.ep, eq.ep, schemes.ep, schemes_vec.ep (+ machine-checked nat_lemmas.ep). Pulled in with # import header directives.
  • examples/embedded/ — ordinary Nim programs whose Eponym-checked definitions are elaborated by eponymBlock at compile time, then used from plain Nim: Paxos, DCP convex optimization, QTT borrow-checking, session types, sensor fusion. Each has header comments explaining what the dependent types are buying.

Editor support

Eponym includes a Language Server Protocol (LSP) server and a VS Code extension for interactive development with sheds. The extension shows each goal with its context in an inline 2D view, and provides Refine, Give, and Case-split actions that update the source and refresh remaining goals.

  • Try the shed walkthrough for guided examples of the editor actions.
  • Find setup and usage instructions in the VS Code extension guide and user guide.
  • Browse the extension source.
  • The Nim LSP implementation is in src/eponym/lsp.nim.

Trust model

docs/trust-model.md states what the system checks and guarantees — and what is your problem: explicit Type l universes (#52), unchecked positivity of data declarations (#33), termination beyond single-function structural recursion (#42), and arbitrary type-level host programs.

Layout

  • src/eponym/elab.nim, unify.nim, preterm.nim, parse_surf.nim, mac_surf.nim — the elaborator.
  • src/eponym/eponym.nim — finally-tagless ETT (evaluator, printer, checker).
  • src/eponym/eponym_init.nim — initial-encoding ETT (de Bruijn AST, evaluator, infer/check/areEqual). The elaborator's target.
  • src/eponym/lsp.nim — language server (Experiment 7).
  • plan.org — experiment plan and research tracks.
  • decisions.org — design decision log.
